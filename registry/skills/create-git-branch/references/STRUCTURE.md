# Последовательность Создания Ветки

Этот reference описывает обязательные проверки для skill `Create Git Branch`.

## Входные Данные

До изменения Git-состояния агент должен иметь все части имени ветки:

- номер задачи с ключом проекта в нижнем регистре, например `om-1855`;
- один из типов: `bug`, `feature`, `refactoring`;
- scope продуктовой области или shared-сущности;
- короткое описание в kebab-case.

Итоговый формат определён project rule:

```text
<task-number>-<task-type>-<scope>-<short-description>
```

## Обязательный Порядок Операций

1. Выполни `git status --short` и `git branch --show-current`.
2. Если переход на `main` может затронуть незакоммиченные изменения, не
   выполняй `git switch`, `git stash`, `git reset` или очистку рабочего дерева.
   Сообщи пользователю, что нужно сохранить, закоммитить или явно отложить
   изменения.
3. Выполни `git fetch origin main`.
4. Перейди на `main`, если она не открыта: `git switch main`.
5. Выполни `git pull --ff-only origin main`. Эта команда исключает
   автоматический merge-коммит при расхождении локальной и удалённой веток.
6. Проверь существование имени: `git show-ref --verify --quiet
   refs/heads/<branch-name>` и `git ls-remote --exit-code --heads origin
   <branch-name>`.
7. Если обе проверки не нашли ветку, выполни `git switch -c <branch-name>
   main`.
8. Подтверди результат через `git branch --show-current` и `git status
   --short`.

## Условия Остановки

Остановись без создания ветки, если:

- `git fetch`, переключение на `main` или fast-forward обновление завершились
  ошибкой;
- нужны части имени ветки, но пользователь их не указал;
- ветка с таким именем уже существует локально или на `origin`;
- рабочее дерево не позволяет безопасно переключиться на `main`.

Не подменяй `main` текущей веткой и не создавай ветку от SHA, если `main` не
удалось обновить.
